Project overview

A smart pillbox system in use in the K-Hub community, designed for people with narcolepsy and other sleep disorders. Independent compartments, explicit confirmation, and three-device sync make dose records verifiable. The product was shown at the 11th Open Source Conference and has received pro bono supply-chain support.

DESIGN & EVIDENCE

Separate removal, confirmation, and synchronization

The product is in use in the K-Hub community. This is an interaction-state illustration, not a hardware test record. Explore the online demo to see the flow.

  1. 01

    Open / remove

    Independent compartments map to separate actions. Opening a lid or removing a pill does not mark a dose as taken.

  2. 02

    Confirm explicitly

    Only an explicit user confirmation creates the record, preserving the unconfirmed state.

  3. 03

    Synchronize devices

    Phone, pillbox, and watch reflect the handled state and end duplicate reminders.

How to verify

In the three-device demo, inspect the unconfirmed state after removal, which states synchronize after confirmation, and when reminders end.

Features · scenarios · needs · value

Core features

  • 四格独立内盖：每一格单独开合，取药动作可被硬件识别
  • 提醒终端：屏幕显示时间与状态，确认键完成本人服药确认
  • 三端同步：手机通知 + 药盒灯光 / 振动 / 铃声 + 手表提醒，任意一端处理即全部结束
  • 库存与余量：按格记录数量与单位，撤销按原单据回滚，不把「100mg」猜测成粒数
  • 离线扫码登记：Camera2 + ZXing 本地识别，扫描图片不上传
  • 三维实时镜像：three.js 复刻药盒与手表，没有实物也能演示完整流程

Application scenarios

  • 发作性睡病患者服药后的记忆空白：用可查证的记录替代回忆
  • 家属远程确认：区分「未来计划」「漏服」「跳过」与「补记」，避免未到时间的误报
  • 锁屏状态下的准时提醒：前台服务保证闹钟不被系统延迟
  • 展台与评审演示：三维药盒镜像在无硬件条件下还原三端联动

Needs addressed

  • 用户需要的不是更多提醒，而是「我到底吃没吃」的确证
  • 取药动作不等于服药，记录必须来自患者本人的显式确认
  • 家属端的「全部正常」可能只是时间还没到，需要区分状态而非一律绿灯
  • 罕见病人群对隐私敏感，数据应留在本地与家庭局域网

Commercial value

  • 开源硬件方案降低复制成本，便于公益组织与病友社群二次开发
  • 硬件 + 软件 + 家属端的组合可延伸为长期用药管理服务
  • 以罕见病为切入点的无障碍设计，可迁移到更广泛的慢病用药场景
  • 本地优先的数据边界，契合医疗健康类产品对隐私的要求
