## 保留精度的运行时优化

- 实际绘制采集发现后方章节展具仍贡献较多调用。采集只在 `?profile=render` 启用，记录真实 `renderBufferDirect` 提交、各通道 CPU 墙钟和可用设备上的异步 GPU 计时；不把 CPU 墙钟称为 GPU 成本，普通访问不包装绘制。
- 能力展具的 12 个相同晶体球使用实例绘制。顶点、索引、位置、连线和粒子数量保持；晶体着色器保留每个球体的局部坐标及实例法线变换。其他独立动画仍按原对象运动。
- 旧介绍屏被 v21 模型完全替换时，跳过整个物理屏组，保留同一个世界锚点投影 DOM。后续章节展具没有按章节硬切隐藏，镜头环绕中继续存在。
- 动态光尘加入覆盖完整年龄、种子和精灵余量的局部包围体，允许正常视锥裁剪。裁掉的是镜头外无贡献的对象，颗粒数和运动保持。
- 同一介绍相机下，两个未受控负载样本的主场景平均调用约 384 → 371；无反射捕获的单帧总调用 404 → 391，档案根提交 306 → 293。采集窗口及反射节奏不同，不把累计通道均值与单帧计数混加，也不据此宣称持续帧率提升。原始证据为 `draw-parts-before.json`、`draw-profile-after.json`。

## 最后收尾：启动卡顿诊断

用户随后要求核对打开网站的卡顿原因并提供解决方案。当前内置预览的普通访问与临时关闭网络缓存访问均保持软件渲染。742×674 的单次本地无网络缓存样本：场景就绪 3173.6 ms，关键模型等待 119.9 ms，着色器准备 641.1 ms，初始光照准备 383.3 ms，持续帧率约 1.0 fps，JS 渲染提交均值 15.60 ms；quality=1.00。这些阶段有前置工作和交叠，不能直接相加，也不是互联网首访基准。关闭缓存的诊断状态已恢复。

当前实际 WebGL 字符串为 `ANGLE (Microsoft, Microsoft Basic Render Driver (0x0000008C) Direct3D11 vs_5_0 ps_5_0, D3D11)`。这是软件光栅化路径。主线程提交计时与约一秒墙钟帧间隔相差很大，结合驱动证据，软件图形路径是当前预览持续卡顿的首要问题；没有 GPU 计时能力，尚不能给出星云、透射、反射或 Bloom 的真实 GPU 耗时占比。设备管理中有独显并不能证明当前上下文正在使用它，系统浏览器的硬件加速表现尚未测得。

另一个已确认的开销：介绍阶段 `createStarport` 无条件请求完整舰队和星港，实际响应分别为 6,074,716 / 6,373,852 字节，合计 12,448,568 字节。该样本两个请求分别约 822 / 804 ms，并发计时不能相加；它们不是首屏关键模型等待列表的成员。代码证据位于 `assets/js/immersive-starport.js`。应在进入创作星图的意图阶段准备完整资产，保持序章所需的星海和观测站不延后；项目舱的共享舰队模型应按真正使用时机加载。该加载重排仍为解决方案，未在收尾诊断中冒充已经实现。

还发现先前所称“入口缓存版本统一”不准确：国际化模板和旧入口的 CSS / 数据 / boot 脚本保留 v21.7，运行模块已经是 v21.12。本轮实际修正为生成器单一 `assetVersion` 和模板占位符，重建 36 个国际化文件，旧入口同步；新增回归直接检查四个发布入口。此问题会使生产缓存存在新旧版本混用风险，没有证据将它当作 1 fps 的主因。

解决顺序：先在系统 Chrome / Edge 核对 WebGL 硬件加速和真实适配器，必要时修正应用 GPU 偏好并重启；然后将未使用模型移出首屏解码/上传和编译阶段；在硬件计时可用时定位各通道，再做保守空体积跳过、静态构件批处理、共享颜色/深度与按变化失效的缓存优化。保留完整模型、粒子数量和视觉目标，分别验收首次打开、连续阅读、快速环绕与返回场景。建议目标：目标桌面设备连续交互接近 60 fps、p95 帧时间不超过 25 ms；这是验收目标，当前未通过。

诊断原始数据：`.workbuddy/qa-v21-12/performance-normal.json`、`performance-cache-off.json`。微软对 WARP 的说明：<https://learn.microsoft.com/en-us/windows/desktop/direct3d11/overviews-direct3d-11-devices-create-warp>；Chromium 说明 WebGL 工作异步发送至图形进程：<https://www.chromium.org/developers/how-tos/trace-event-profiling-tool/trace-event-reading/>。二者支持软件渲染与提交时间边界的解释，不替代本机 GPU 通道计时。

缓存修复后的最后普通中文入口已重新加载：实际资源版本均为 `cinematic-v21.12`，诊断参数为空、quality=1.00、约 1.0 fps、当前运行警告/错误为空，驱动仍为 Microsoft Basic Render Driver。默认视口已恢复，页面留在介绍章。最终数据和网页截图为 `final-state.json`、`final-logs.json`、`overview-final.jpg`。这确认了缓存修复已生效，也确认它没有解决软件图形路径的持续卡顿。
