## 实际修改

**编译冻结**

- `immersive-nebula-pass.js`、`immersive-volume-field.js`：6 路分支只负责选择参数，步进函数只调用一次。D3D 编译器原先把整段步进内联 6 份，单个着色器冷编译 51–69 s，现在约 2 s。积分采样与原来一致。
- `immersive-lightstage.js`：环境探针在实际绘制的线性 HDR 立方体目标上 `compileAsync`。原先按画布默认的 sRGB 输出编译，正式捕获时又在主线程同步编译一次。立方体固定为 128，低档只减少步数。PMREM 尺寸是所有物理材质的着色器宏，原先画质跌破 0.75 时切到 64，整个观测站会重新编译。
- `immersive-shader-preparation.js`：
  - 全屏后期通道（星云、粒子合成、Bloom、输出、胶片）在启动时与探针、模型并行预编译。
  - `createShaderWarmup` 在场景就绪后，按"观测站/档案 → 星港/舰队 → 其他"的顺序，后台分批编译从未编译过的材质（含镜面反射的薄玻璃变体）。
  - `compileBeforeReveal` 让星港、舰队、作品舰、阅读展具、远景栖居地和星域世界先编译、后显示，编译期间保留程序化后备；超时 4 s 后直接显示。
- `immersive-light-rig.js`（新增）：模块自建的点光移到摄像机不渲染的图层，由 6 个固定灯位按"强度 × 覆盖到屏幕的范围"承载，替换时淡入淡出。原先可见点光数在 5–11 之间变化，每次变化都让所有受光材质重编译。
- `immersive-hardware.js`：新增 `instancedMesh` / `instancedMaterial`。实例网格使用私有材质副本，uniform 仍共享，绘制前同步源材质的颜色、透明度和版本。7 个材质原先同时用于实例和普通网格，会生成 `instancing 0/1` 两套程序，还会每帧重算程序参数。改用的模块：档案、驾驶舱、空间站、行星、星域、作品舰。
- `immersive-optical.js`：光学薄膜改为 `forceSinglePass`。8% 不透明度下前后面的绘制顺序看不出差别；原先双面透明会让材质每次绘制都被标记为需要更新。

**GPU 负载与帧节奏**

- `immersive-cosmos.js`：画布关闭 `antialias` 和 `alpha`，所有像素都由最后一个不透明通道写入。
- `immersive-frame-budget.js`：
  - `createRenderPacer` 从回调间隔学习刷新率，按整数个刷新出帧：165 Hz → 55 fps，144 Hz → 72 fps，60/120/180/240 Hz → 60 fps。
  - `graphicsProfile` 按适配器分档：独显为 `cinematic`；集显为 `balanced`（2×MSAA、透射 0.75）；软件渲染为 `light`。设置中的"完整/轻量画质"可以覆盖档位。
  - 自动画质先降分辨率；降到下限仍慢才降档，恢复时先恢复档位。恢复后很快又降档的，下次恢复的等待时间加倍。
- `assets/vendor/three-0.161.0/build/three.module.js`：回移植 r172 的 `renderer.transmissionResolutionScale`，并增加 `transmissionSamples`。默认值保持 r161 原有行为。补丁记录在 `scripts/vendor-three-patches.mjs`，`vendor-three.mjs` 重建时会重放；`manifest.json` 同时记录上游 SHA256（`e7348ab8…`）与实际 SHA256（`fb0b8232…`）。

**资源**

- `immersive-audio.js` 与 `assets/audio/**/*.m4a`：序章（2.24 MB → 0.28 MB）、结尾主题（7.2 MB → 0.91 MB）和全部音效改用 AAC，浏览器不支持或解码失败时回退 WAV。无缝循环的 Bed 仍用 WAV，避免 AAC 编码填充在循环接缝处留下空隙。解码后的时长、声道和峰值与原文件一致。

**版本与测试**

- 缓存标识统一升级为 `cinematic-v21.19`：`build-international.mjs` 的 `assetVersion`，以及沉浸式模块内的导入地址。重建了 40 个国际化文件。
- 新增 26 项测试，涵盖：单一调用点、探针编译目标与固定尺寸、全屏通道预编译、后台编译、先编译后显示、灯光池、实例材质副本、刷新率对齐、分档与降档退避。
- 新文件已 `git add` 暂存，因为部署完整性测试读取 Git 追踪清单。没有提交。

## 未解决与边界

- 这些数据来自无头 Chrome。无头模式没有真实显示器的垂直同步，渲染帧率按节拍器目标计算；165 Hz 下的出帧匀速性是仿真结论，需要在真实窗口里确认。
- 本机 Chrome/Edge 默认使用 Iris Xe。在 Windows"设置 → 系统 → 屏幕 → 显示卡"里为 Chrome/Edge 选择"高性能"，网站会走 `cinematic` 档（RTX 3070）。本轮没有改动系统设置，也没有测量 3070。
- 页面加载时仍有约 0.8 s 的主线程初始化（模块解析和程序化几何生成），发生在启航界面显示期间。
- 集显上自动画质会停在分辨率下限，画面偏软。后续可以加入后处理抗锯齿，再按方案第 3 批削减星云和地面成本，把分辨率换回来。
- 本轮浏览路径以外的状态（移动端、英文、减少动态）只有自动测试覆盖，没有逐一实测。
