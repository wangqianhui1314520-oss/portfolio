功能 · 场景 · 需求 · 价值

核心功能

  • 端侧结论卡：首页直接给出「家里都还好」或「我不确定」，替代运动告警
  • 多摄像头取流 + HomeBase 端侧推理：判断完整发生在家庭内网
  • 跨摄接力：单一目标在多个摄像头之间交接跟踪，离开画面不丢失
  • 置信度机制：没把握时明确说「我不确定」，不把模糊判断推给用户
  • 隐私边界：不做疾病标签，不做人脸识别

应用场景

  • 上班 / 出差期间的宠物看护：远程确认猫狗状态
  • 已装多台 eufy 摄像头的家庭：客厅、阳台、食盆区多点位
  • 老人与幼儿家庭的日常活动安心确认（非医疗诊断）
  • 短时外出（购物、接送）期间的家中概况确认

解决的需求

  • 用户要的是「我知道家里没事」，不是「检测到运动」
  • 告警噪音与误报训练用户忽略通知，需要的是结论
  • 云端识别带来隐私顾虑，端侧推理让数据不出家门
  • 多摄像头各自为政，缺少跨屏的连续状态

商业价值

  • 复用存量硬件：不增加摄像头采购，激活已售设备与 HomeBase 算力
  • 从硬件差价转向服务价值：结论卡支撑订阅制安心服务叙事
  • 场景创新差异化：以可核验结论区别于运动检测告警红海
  • 隐私即卖点：端侧处理契合家庭安防数据敏感的产品趋势
DESIGN APPROACH

从问题到体验

用户要的不是「检测到运动」，而是「我知道家里没事」。要让已经装在屋里的摄像头给出一个可核验的结论，而不是又一条告警。

Anker 黑客松智能安防赛道团队作品。复用家庭已有的 eufy 多摄像头与 HomeBase 端侧算力，首页直接呈现结论卡。我在团队中负责端侧硬件与推理：取流、端侧推理、Jev 决策服务与跨摄接力。

让判断发生在家庭内网

取流与推理跑在 HomeBase 与摄像头一侧，结论在本地生成；不做疾病标签，不做人脸识别，减少隐私数据外流。

给结论一个置信度

结论卡分四态呈现：有把握时给出「家里都还好」，没把握时明确说「我不确定」，不把模糊的判断推回给用户。

跨摄接力保持连续

单一目标在多个摄像头之间交接跟踪，离开单个画面的宠物不会立刻丢失，结论在时间上保持连续。
